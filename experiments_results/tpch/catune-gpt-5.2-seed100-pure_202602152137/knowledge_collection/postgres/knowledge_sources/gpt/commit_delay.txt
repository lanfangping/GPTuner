Set `commit_delay` to **0 µs** (default) unless you have enough concurrent committing sessions to batch WAL flushes—then try **100–1000 µs** (rarely >**10,000 µs**) and only keep it if benchmarks show improved throughput **without unacceptable added commit latency**, typically requiring `commit_siblings` (e.g., **5–10+**) so the delay only happens when several backends are ready to commit.
