{'suggestion': 'Configure `max_connections` (set at server start; default is ~100 and may be constrained by kernel limits) to match the maximum number of *simultaneous active* client sessions you truly need. Prefer using a connection pooler: with pooling in transaction mode, set `max_connections` to a low multiple (~2–5×) of the server’s CPU core count; with pooling in session mode, set it to the minimum number of concurrent sessions that cannot be queued; without pooling, set it to the required concurrent users but expect suboptimal performance. Ensure the server has enough memory for the chosen value (connection overhead can be significant and grows with per-connection memory such as `work_mem`, so many deployments keep `max_connections` around ~100–300 and rely on pooling for higher client counts). If you use a standby, set the standby’s `max_connections` to be ≥ the primary’s to avoid standby queries being blocked.'}
