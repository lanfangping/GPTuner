To set the `vacuum_freeze_table_age` parameter in PostgreSQL, configure it to a value between 0 and 2 billion (typically 150 million to 200 million for most workloads) which determines the age threshold at which VACUUM will perform a whole-table scan to freeze old tuples, where setting it too low (e.g., below 50 million) causes excessive I/O from frequent whole-table scans, while setting it too high (e.g., above 1.5 billion) risks transaction ID wraparound failures.
