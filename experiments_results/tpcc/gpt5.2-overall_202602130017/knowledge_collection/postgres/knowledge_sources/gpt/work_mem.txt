Set `work_mem` so that **(per active sort/hash operation) × (peak concurrent operations per session) × (peak concurrent sessions)** comfortably fits in RAM after accounting for `shared_buffers` and OS cache—e.g., on a **32 GB** server with **8 GB shared_buffers**, if you expect **50 concurrent sessions** and ~**2** sort/hash ops each, target about **(32−8) GB / (50×2) ≈ 240 MB**, then cap it conservatively (often **16–64 MB** is a safe starting range) to avoid worst‑case memory blowups.
