Set `enable_partition_pruning` to **on (default)** for almost all workloads to let PostgreSQL skip irrelevant partitions at plan and execution time; only set it **off** temporarily for **debugging/benchmark comparisons** (e.g., expect queries over a partitioned table with **100+ partitions** to scan **only the few matching partitions** instead of all **100+** when it’s on, assuming the predicate can be used for pruning).
