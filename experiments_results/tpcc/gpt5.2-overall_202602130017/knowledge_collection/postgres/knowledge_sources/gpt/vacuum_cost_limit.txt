Set `vacuum_cost_limit` based on how much vacuum you can “spend” per worker: start with the default **200**, and if autovacuum can’t keep up increase gradually (commonly **1000–5000**, sometimes up to **10000** on fast SSDs), keeping in mind the effective throughput is roughly **vacuum_cost_limit / vacuum_cost_delay** (e.g., **200/2ms ≈ 100k cost/s** vs **2000/2ms ≈ 1M cost/s**) while watching for increased I/O latency or user-query slowdown.
