Set `max_locks_per_transaction` high enough to cover the peak number of distinct relations (tables/indexes/partitions) a single transaction might lock—typically leave it at **64** for OLTP, raise to **128–256** for complex/partition-heavy workloads, and if you see “out of shared memory” lock errors, increase it (e.g., **64 → 128 → 256**) and restart; note each doubling increases the shared lock table memory usage roughly proportionally.
