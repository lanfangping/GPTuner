Set `max_connections` to the smallest number that safely covers peak concurrent sessions—estimate it as **(peak active app connections + admin/maintenance) with ~10–20% headroom**, e.g., if you expect **80** app sessions plus **10** extra, set **`max_connections` ≈ 100** (and if you need **hundreds/thousands**, keep Postgres at **~100–300** and use a connection pooler like PgBouncer for the rest).
