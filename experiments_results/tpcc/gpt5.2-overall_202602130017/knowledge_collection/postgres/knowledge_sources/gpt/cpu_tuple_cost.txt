Set `cpu_tuple_cost` to approximate the **CPU time to process one row relative to a sequential page read**: start from the default **0.01**, **decrease to ~0.003–0.008** on modern fast CPUs if PostgreSQL underestimates CPU speed (favoring seq scans too much), or **increase to ~0.01–0.03** if CPU is the bottleneck (favoring index/IO plans more); validate by comparing `EXPLAIN (ANALYZE, BUFFERS)` plan choices and runtimes before/after.
