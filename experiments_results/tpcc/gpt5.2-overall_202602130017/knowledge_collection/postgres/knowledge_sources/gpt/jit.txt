Set `jit` to **on (default)** when your workload includes **long-running/complex queries** where each query runs for **tens–hundreds of milliseconds or more (≈ ≥100 ms)** and CPU is a bottleneck, but set it **off** for **latency-sensitive OLTP** with **many short queries (≈ <5–10 ms each)** or if you see regressions—optionally control it more precisely by keeping `jit=on` and raising thresholds like `jit_above_cost` from **100000** to **200000–500000+** so only very expensive queries trigger JIT.
