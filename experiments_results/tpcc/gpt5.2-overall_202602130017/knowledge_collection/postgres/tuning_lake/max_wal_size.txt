{'suggestion': 'Increase `max_wal_size` (default 1GB; values without units are MB) to a level that lets automatic checkpoints be driven primarily by the checkpoint timeout rather than WAL size, provided you have sufficient disk space. Treat it as a soft cap on WAL growth before an automatic checkpoint is triggered (it can be exceeded under heavy load, archive failures, or high `wal_keep_size`). Choose a size roughly based on what you can afford to accumulate between checkpoints—commonly ~5–10% of the data directory or 2–10× expected WAL generated per checkpoint interval (e.g., ~4–16GB for small/medium systems and ~32–128GB+ for write-heavy systems). Be aware that raising `max_wal_size` can increase crash recovery time, and it must be set in `postgresql.conf` or via the server command line.'}
