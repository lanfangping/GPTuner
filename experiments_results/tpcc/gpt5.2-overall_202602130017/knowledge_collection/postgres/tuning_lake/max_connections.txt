{'suggestion': 'Set PostgreSQL `max_connections` to the minimum number of simultaneous client connections you must support (it controls the maximum concurrent clients; default is ~100 and may be constrained by OS/kernel limits) and remember it must be configured at server start. Prefer using a connection pooler (e.g., PgBouncer) so Postgres can keep `max_connections` relatively low: in transaction-pooling mode, a common guideline is ~2–5× the number of CPU cores; in session mode (or without pooling), size it to the number of concurrent users/sessions that cannot be queued, adding modest headroom for admin/maintenance. If you expect very large numbers of client connections, keep Postgres in the low hundreds and let the pooler handle the rest. On a standby/replica, ensure `max_connections` is at least the primary’s value so queries are allowed.'}
