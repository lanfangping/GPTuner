{'suggestion': 'Configure `autovacuum_work_mem` in `postgresql.conf` (or via the server command line) to control the per-autovacuum-worker memory limit (unitless values are in kB; default is to use `maintenance_work_mem`). Size it to roughly 1–4% of system RAM per worker, and cap it so that `autovacuum_work_mem × autovacuum_max_workers` stays within about 5–10% of RAM to limit worst-case concurrent autovacuum memory usage. Note that this setting does not affect manual `VACUUM`, and increasing it beyond an effective ~1 GB cap will not improve dead tuple identifier collection.'}
