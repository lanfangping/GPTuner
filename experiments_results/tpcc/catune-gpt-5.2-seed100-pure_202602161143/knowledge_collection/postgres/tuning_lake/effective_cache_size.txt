{'suggestion': 'Set `effective_cache_size` to a realistic estimate of the total cache PostgreSQL can effectively rely on for planner cost estimates—i.e., `shared_buffers` plus the OS page cache (not memory actually allocated/reserved by this setting). A higher value tends to favor index scans, while a lower value tends to favor sequential scans. Choose a value based on available RAM and workload: a common starting point on a dedicated PostgreSQL server is roughly 50–75% of system RAM (e.g., ~16–24GB on a 32GB host), and you can refine it using an estimate like: system RAM − (shared_buffers + work_mem * max_connections * 2) * 1.1 (use a lower value if the machine is not dedicated to PostgreSQL).'}
