{'suggestion': 'Use `random_page_cost` to tell the PostgreSQL planner how expensive a random (non-sequential) page read is compared to a sequential read (default 4.0). Lower it when random access is relatively fast—e.g., SSDs or mostly-cached data (often around 1.1–1.5; ~1.2 is a common SSD-like value)—to make index scans more attractive; raise it if random/index reads are truly much slower. The default 4.0 roughly reflects an assumption that random I/O is far slower than sequential, with many random reads served from cache. After changing it, validate plan choices with `EXPLAIN (ANALYZE, BUFFERS)` and adjust if queries still over- or under-prefer index scans.'}
