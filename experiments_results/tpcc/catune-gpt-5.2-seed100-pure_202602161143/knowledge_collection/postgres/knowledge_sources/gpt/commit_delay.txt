Set `commit_delay` to **0 µs** by default (common for low/moderate write concurrency), and only try a nonzero value when you have **high concurrent commit rate** (e.g., **dozens–hundreds of commits/sec across many sessions**) and the server is not CPU-bound—then start around **100 µs**, test **100–1000 µs** (rarely above a few ms), and use it only together with `commit_siblings` (typically **5–10**) so the delay is applied only when at least that many other backends are ready to commit.
