Set `vacuum_multixact_freeze_table_age` to a value that ensures tables are proactively “multixact-frozen” well before wraparound—typically keep the default **150,000,000** for most systems, but if you want more aggressive freezing (to reduce emergency anti-wraparound vacuums) lower it to around **50,000,000–100,000,000**, and if you need to reduce vacuum overhead on very large/low-risk clusters you might raise it modestly (e.g., **200,000,000**) while staying safely below the hard wraparound limit (on the order of **~2 billion** multixact IDs).
