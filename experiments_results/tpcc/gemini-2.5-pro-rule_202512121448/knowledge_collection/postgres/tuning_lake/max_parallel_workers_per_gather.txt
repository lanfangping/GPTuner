{'suggestion': 'This knob sets the maximum number of workers for a single part of a parallel query, with a default of 2. For high throughput OLTP systems, it is often better to leave it at 1 or 2. For analytical/DW systems, you can raise it, but it should be set to a fraction of the available CPU cores. Be aware that a query using 4 workers could consume up to 5 times the resources of a non-parallel query. This parameter is affected by `work_mem`, so we recommend reviewing that value accordingly. The value cannot exceed the server-wide `max_parallel_workers` limit.'}
